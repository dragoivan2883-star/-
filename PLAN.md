# План локального прототипа Agenta

Статус: **предварительно согласован 10 ноября 2026 года с уточнениями заказчика**. Основа исследования — [SITE_ANALYSIS.md](SITE_ANALYSIS.md). План относится только к локальной тестовой модели. Интеграция с рабочим сайтом и его API исключена.

## Цель

Показать агенту направление на ремонт через модальное окно при входе, обеспечить создание полноценной тестовой заявки и дать агенту и администратору отдельный реестр с разграничением доступа. Все данные в прототипе вымышленные; созданные заявки хранятся в локальной базе и переживают перезапуск.

## Согласованные требования

1. Рекламный баннер — только всплывающее модальное окно при входе агента. Компактного баннера на главной нет.
2. Закрыть окно можно только кнопкой «Х» или переходом к меню выбора направления. Клик по подложке, Esc и таймер окно не закрывают.
3. После закрытия окно показывается при следующем входе не раньше чем через 48 часов. После создания первой заявки конкретным агентом повторный показ прекращается.
   В модальном окне используется предоставленный заказчиком оригинальный PNG «Зарабатывайте на ремонте автомобилей» без изменения текста, цветов, композиции и логотипа.
4. Кнопка «Оставить заявку» постоянно видна в верхней панели и открывает меню выбора направления.
5. Отдельная форма для выбранного направления собирает город, данные клиента, автомобиля и описание повреждений и создаёт тестовую заявку.
6. Заявки сохраняются в локальной базе данных, без зависимости от состояния браузера.
7. Отдельный реестр даёт поиск, фильтры, статусы и просмотр карточки.
8. Роли: «Агент» видит только свои заявки; «Администратор» видит все.
9. Администратор меняет статус, назначает ответственного и добавляет комментарии. История комментариев сохраняется в базе.
10. Прототип не вызывает рабочий API Agenta и не использует реальные клиентские данные.

## Первый этап — проверяемая локальная вертикаль

- Создать структуру проекта, локальный сервер и SQLite базу с миграцией при запуске.
- Сделать демонстрационный вход с двумя вымышленными пользователями разных ролей, общую оболочку, главную и постоянную кнопку в шапке.
- Реализовать модальное окно с правилом 48 часов, переходом к меню выбора направления и прекращением показа после первой заявки.
- Создать форму и сохранение заявки, базовый реестр и карточку. Доступ к данным ограничить на сервере по роли и владельцу.
- Запустить и показать работающий интерфейс; проверить повторный вход, перезапуск сервера и изоляцию заявок агента.

## Второй этап — завершение реестра и администрирования

- Доработать поиск и фильтры по статусу, дате и ответственному; пустые и ошибочные состояния.
- Смена статуса администратором с сохранением в SQLite реализована после первого этапа.
- Добавить назначение ответственного и комментарии с сохранением.
- Проверить все сценарии на широком и узком экране, клавиатурную навигацию и валидацию формы.
- Представить итоговый прототип для отдельного согласования. Любая будущая интеграция обсуждается после этого отдельно.

## Дополнение к текущему прототипу

- Баннер при открытии плавно поднимается снизу. Правила автоматического показа, повторного тестового открытия и закрытия остаются прежними.
- Администратор меняет статус в карточке заявки; сервер проверяет роль и допустимые значения, а SQLite сохраняет изменение после перезапуска.
- С 12 ноября 2026 года кнопка баннера «Оставить заявку» открывает меню трёх направлений: ОСАГО — 1%, КАСКО — 2%, коммерческий ремонт — 3%. Кнопка в шапке ведёт туда же. Для каждого направления открывается отдельная форма с обязательным полем «Город».
- Вид ремонта, процент и город сохраняются в SQLite и показываются в реестре и карточке. Существующим заявкам при миграции не назначается вымышленный вид ремонта или город.
- Города в новых заявках ограничены Казанью, Нижнекамском и Набережными Челнами. Для ОСАГО выбирается одна из пяти компаний: Альфа, Ингосстрах, Ренессанс, МАКС, Пари. Для КАСКО выбирается одна из семи: Зетта, Альфа, Ингосстрах, Пари, МАКС, Совком, Ренессанс. Ренессанс по КАСКО доступен только в Казани. Для коммерческого ремонта страховщик не указывается. Правила проверяются в форме и на локальном сервере; ранее созданные заявки сохраняются без подстановки компании.
- Новые заявки могут отправляться письмом на `admin@alternativa-kzn.ru`. До отдельного теста почта выключена. Тестовый режим направляет письмо в указанный заказчиком ящик через настраиваемый SMTP. Результат попытки сохраняется в локальной базе; сбой отправки не отменяет создание заявки.

## Правила и допущения для первого этапа

- «Вход» в прототип — выбор демонстрационной роли, а не авторизация Agenta. Предусмотреть минимум двух агентов, чтобы проверить видимость только своих заявок.
- Для тестовой заявки использовать обязательные поля: направление ремонта, город, имя и телефон клиента, марка, модель, госномер автомобиля, описание повреждений. Дополнительные поля можно уточнить после показа.
- Начальный статус — «Новая»; для отображения в реестре предусмотреть «В работе», «Ожидает клиента», «Завершена», «Отменена».
- Время закрытия баннера хранить в локальной базе по агенту. Пока заявок нет, при входе после 48 часов баннер появляется снова. Создание первой заявки отменяет показ навсегда для этого агента.
- Демонстрационные сведения явно помечаются как тестовые. Реальные логины, пароль, полисы и клиентские записи в проект не переносятся.

## Критерии приёмки первого этапа

1. Модальное окно показывается при входе агента без заявки, закрывается только двумя разрешёнными способами и соблюдает интервал 48 часов.
2. Кнопка в шапке открывает меню трёх направлений с любого экрана; выбор направления открывает соответствующую форму.
3. Заявка с направлением, городом, клиентом, автомобилем и повреждениями появляется в реестре и остаётся после перезапуска приложения.
4. Агент не получает чужие заявки даже прямым запросом к серверу; администратор видит все.
5. В исходниках и локальной базе нет данных с рабочего сайта; обращения к его API отсутствуют.
